## Unit Tests
### T-002 unit tests
- **Intent:** [INT-0003](../../../intents/INT-0003-engineering-baseline.md), [INT-0005](../../../intents/INT-0005-deterministic-simulation-testing.md)
- **new** `every_method_reaches_through_every_forwarder` (`crates/sim/tests/contract.rs`): for `&SimFs`, `Rc<SimFs>` and `Arc<SimFs>`, a generic function calls each of the trait's 16 methods. After each syscall method the trace has gained that syscall's line with its path. `has_executable_bit` and `name_rules` return what was set on the filesystem. `point` raises the count `reach` reports.
- **new** `point_has_no_default_body` (`crates/sim/tests/points.rs`): the trait's source declares `fn point(&self, name: &'static str);`, ending in a semicolon. With a body there, a forwarder that left `point` out would compile and drop points.
- `points_reach_through_every_forwarder`: unchanged.
- **new** `hex_is_two_lowercase_digits_per_byte` (`crates/hash/tests/vectors.rs`): each of the 256 byte values gives its two digits; the empty slice gives the empty string; a `HashRef`'s text form ends with `hex` of its digest.
- The four `*_is_reproducible` tests, unchanged, assert Sprint 5's literals. They are the evidence that no syscall moved.

### T-003 unit tests
- **Intent:** [INT-0014](../../../intents/INT-0014-working-copy-and-workspaces.md), [INT-0035](../../../intents/INT-0035-scale-and-asynchrony.md), [INT-0009](../../../intents/INT-0009-reversible-by-default.md)
- **new** `op_log_lists_once_and_counts_invalid_files` (`crates/store/tests/store.rs`): a store with three ops, one more op file with a flipped bit, one whose name parses but whose body does not decode, and one `tmp-` file. `op_log` returns the three ops and counts two invalid files. The trace shows one `list` of `ops/` and one `read` of each of the five op files, and none of the `tmp-` file.
- **new** `open_with_log_lists_ops_once_and_objects_never` (`crates/store/tests/store.rs`): on a store with ops, the trace of `open_with_log` holds one `list` of `ops/`, none of `objects/`, and the same four syncs as `open`. It returns the same ops as `ops()`.
- **new** `open_with_log_needs_the_layout` (`crates/store/tests/store.rs`): with `objects/` missing, with `ops/` missing, and with both missing, it fails with the error `open` gives, and the filesystem's snapshot is unchanged.
- **new** `open_and_one_command_read_the_op_log_once` (`crates/workspace/tests/workspace.rs`): a repository with five ops is opened and one command is run, for each of `snapshot` (with and without an edit to record), `status`, `new_change`, `log`, `undo`, `restore` and `restore_view`. In the trace from before `open` to after the command:
  - one line lists `ops/`;
  - no line lists `objects/`;
  - the reads under `ops/` are the five files once each, plus two for each operation the command committed (its parent and its own name).
- **new** `a_second_command_lists_the_op_log_once_more` (`crates/workspace/tests/workspace.rs`): after the first command, `status` adds exactly one listing of `ops/`, and a third command one more.
- `a_failed_snapshot_reports_nothing_stale`, `invalid_op_files_are_refused`, `several_heads_stop_every_command`: unchanged. Each writes through a second handle after a command has finished and expects the next command to stop.
- **new** `accessors_read_what_is_stored` (`crates/workspace/tests/workspace.rs`): after `open`, a second store handle commits an operation over the head whose view names another working-copy changeset. Without any command in between, `working_copy()` returns that changeset and `parent_tree()` its parent's tree.
- **new** `a_damaged_op_stops_open_before_resume` (`crates/workspace/tests/materialise.rs`): a restore is interrupted after its operation is committed, leaving the record. One bit of that op file is flipped. `open` fails with `Corrupt`; the record file is still there with the same bytes; no working-copy file has changed. With the bit put back, `open` resumes and finishes the write.
- **new** `undo_and_restore_scan_once` (`crates/workspace/tests/history.rs`): in the trace of `undo`, and of `restore`, the working copy's top directory is scanned once. An edit made just before each command is in an operation of its own before the operation that moves the working copy.
- `undo_and_restore_snapshot_first`, `two_hundred_pairs_stay_distinguishable`, `edits_during_the_write_are_kept`, `restore_reaches_every_earlier_state`, `undo_after_every_op_type`: unchanged.
- `snapshotting_commands_return_reports`: its comment that `undo` snapshots twice is corrected; its assertions stand.
